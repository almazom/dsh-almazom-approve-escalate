# TC-001 — Plugin skeleton: manifest contract, host face + config WebRoute, build

## User Story

As the operator, I want plugin skeleton: manifest contract, host face + config WebRoute, build, so that the plugin delivers real value end-to-end and can be published with evidence.

## Story Points

3

## Dependencies

None

## Description

As the operator, I want the plugin package skeleton to satisfy the DSH plugin contract exactly, so that `dsh plugin add` mounts it and the client half loads in the browser.

Files:
- `package.json`
- `cordis.patch.yml`
- `src/index.ts`
- `src/client/index.ts`
- `tsconfig.json`
- `tsdown.config.ts`
- `tests/manifest.test.mjs`
- `README.md`

## Implementation Steps

1. Create `package.json`:
```json
{
  "name": "dsh-almazom-approve-escalate",
  "version": "0.1.0",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".": "./lib/index.js",
    "./client": "./lib/client.js",
    "./package.json": "./package.json"
  },
  "files": ["lib", "cordis.patch.yml", "README.md"],
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web" }
  },
  "peerDependencies": {
    "@deepseek-ai/cordis": "^0.1.2-alpha.1 || ^0.1.3-alpha.1 || ^0.1.5-rc.1"
  }
}
```
2. Create `cordis.patch.yml` (row name MUST equal the package name):
```yaml
- insert:
    - id: almazom-approve-escalate
      name: 'dsh-almazom-approve-escalate'
      config:
        preset: 'workspace-write'
        label: 'Approve & escalate'
```
3. Host face `src/index.ts` — reads config, serves it on an official WebRoute, no secrets:
```ts
export function apply(ctx: any): void {
  const config = (ctx.config ?? {}) as { preset?: string; label?: string }
  const body = JSON.stringify({
    preset: config.preset ?? 'workspace-write',
    label: config.label ?? 'Approve & escalate',
  })
  ctx.webServer.registerRoute({
    method: 'GET',
    path: '/almazom-approve-escalate/config.json',
    handler: () => new Response(body, { headers: { 'content-type': 'application/json' } }),
  })
}
```
(Verify the exact `WebRoute` shape against `packages/host/webserver/src/index.ts:41-48` in the reference tree and adapt; the route must appear under the plugin's mounted webServer face.)
4. Client face `src/client/index.ts` stub (TC-002 fills the panel):
```ts
export const inject = ['slots']
export function apply(ctx: any): void {
  ctx.slots.inject('conversation.approval.detail', () => ctx.slots.register(
    { name: 'conversation.approval.detail' },
    () => null,
  ))
}
```
5. Build with tsdown, two entries, `react` marked external and resolved to the host graph:
`tsdown.config.ts`:
```ts
import { defineConfig } from 'tsdown'
export default defineConfig([
  { entry: ['src/index.ts'], outDir: 'lib', format: 'esm', dts: false },
  { entry: ['src/client/index.ts'], outDir: 'lib/client.js', format: 'esm', dts: false,
    external: ['react', 'react/jsx-runtime'] },
])
```
Run `pnpm run build` → `lib/index.js` + `lib/client.js` exist and parse (`node --check`).
6. Structure test `tests/manifest.test.mjs` (node --test): asserts name/patch-row parity, `dsh.bundle.patch`, `dsh.client.platform === 'web'`, `exports["./client"]` file exists, `lib/index.js` + `lib/client.js` parse, patch row `name === package.json name`.

## Acceptance Criteria
- `node --test tests/` exits 0.
- `pnpm run build` exits 0 and produces `lib/index.js` + `lib/client.js`.
- `node -e "console.log(require('./package.json').dsh.client.platform)"` prints `web`.
- `grep -c "dsh-almazom-approve-escalate" cordis.patch.yml` returns ≥ 1 and equals the package name.

## Definition of Done
- Package installs cleanly as a directory dep and its manifest satisfies the contract tests.
- No secrets, no network calls in the host face beyond the local config route.
