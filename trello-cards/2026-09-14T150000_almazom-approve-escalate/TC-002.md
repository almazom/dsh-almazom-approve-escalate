# TC-002 — Approve & escalate panel in conversation.approval.detail slot

## User Story

As the operator, I want approve & escalate panel in conversation.approval.detail slot, so that the plugin delivers real value end-to-end and can be published with evidence.

## Story Points

4

## Dependencies

TC-001

## Description

As the operator, I want the approval card to show an "Approve & escalate" action, so that one click approves the pending request and switches the live session to the configured preset.

Files:
- `src/client/panel.ts`
- `src/client/styles.ts`
- `src/client/index.ts`

## Implementation Steps

1. Panel registered into `conversation.approval.detail` (seat contract: ownerProps `{callId}`; standard seats `useSessionPendingInteraction`, `useSession`, `sessionId`, `useProjection`, `inputActions` — slot-catalog.ts:83-118). Registration lives in `apply` via `ctx.slots.inject(key, () => ctx.slots.register(...))`, no `priority` (CLIENT_NOTES: auto-lower-than-shipped).
2. Fetch plugin config once: `fetch('/almazom-approve-escalate/config.json')` → `{preset,label}`; cache module-level; fall back to defaults on failure.
3. Render with `React.createElement` only, colors from theme CSS vars (`var(--dsw-alias-*)`), CSS via `styles.insert()` (idempotent `<style data-dsh-almazom-approve-escalate>`), a single row: primary button `label` + a hint line `also switches this session to <preset>`. Re-render the shipped detail: look up the correlated tool call via the projection/trajectory seats by `callId` and print its `command` argument (text only) so shadowing loses no information.
4. Click handler (async):
   - escalate: dispatch `/permission <preset>` — try the documented path used by ui-permission-presets (`commands.execute(agentId, line, [])`, ui-permission-presets/src/client/index.ts:219-222); if the sessions seat does not expose it, probe `inputActions` submit of the command line; pin the working path with a fallback chain and a 3s timeout.
   - answer: `const pending = useSessionPendingInteraction(sessionId)`; if `pending && typeof pending.answer === 'function'` → `pending.answer('allowed-once')`; else render graceful note "Preset applied — confirm the request with Allow once."
   - button disabled + spinner state while in flight; errors surface as inline text, never `alert`.
5. Keep the component resilient: any seat missing → render only the hint, never throw (registration failure surfaces in the browser load report).
