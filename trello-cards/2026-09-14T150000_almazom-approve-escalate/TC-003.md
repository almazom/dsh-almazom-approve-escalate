# TC-003 — Isolated-stand E2E: real approval flow, button click, policy switch, GIF

## User Story

As the operator, I want isolated-stand E2E: real approval flow, button click, policy switch, GIF, so that the plugin delivers real value end-to-end and can be published with evidence.

## Story Points

4

## Dependencies

TC-002

## Description

As the operator, I want browser proof on an isolated stand that the button works end-to-end, so that publication claims are behaviorally true.

Files:
- `e2e/stand.sh`
- `e2e/approval_probe.mjs`
- `e2e/*.png`, `e2e/escalate.gif`

## Implementation Steps

1. `e2e/stand.sh`: fresh scratch `DSH_HOME=/tmp/dsh-almazom-escalate/home`, profile install of the plugin (`dsh plugin --profile web add file:$PWD` against the LIVE harness tree `~/projects/dsh-latest` via its CLI), serve on port 39781, wait for 401/200.
2. Trigger a real approval: send one session task that attempts a tool requiring approval under `read-only` preset (one model round, real key from env, value never echoed), keep the session open on the card.
3. `e2e/approval_probe.mjs` (playwright from ~/projects/dsh/ops, cookie auth via curl `/_dsh_login`): assert card shows the button; click it; assert (a) the session permission preset switched to `workspace-write` (projection chip text), (b) the pending approval resolved (card gone / decision logged); screenshots before/after; record frames → GIF ≤10MB.
4. Frames from one run; on any failure fix and re-record from scratch.

## Acceptance Criteria
- `bash e2e/stand.sh` exits 0 and prints the stand URL.
- Probe exits 0 with both assertions logged (`POLICY SWITCHED ✓`, `APPROVAL RESOLVED ✓`).
- `e2e/escalate.gif` exists, ≤10MB, recorded from the passing run.

## Definition of Done
- GIF + screenshots show: card with button → click → preset switched → approval resolved.
